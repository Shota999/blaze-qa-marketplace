# Coverage — რა უნდა დაიფაროს

## სავალდებულო 12 ჯგუფი (ყველა სთორიზე)

1. **ნავიგაცია / ხილვადობა** — გვერდი/ჩანართი იხსნება სწორად
2. **Happy Path (წარმატებული სცენარი)** — ძირითადი ფლოუ ბოლომდე
3. **ვალიდაცია — სავალდებულო ველები** — ცარიელად დატოვება
4. **ვალიდაცია — არასწორი მონაცემები** — ფორმატი, ტიპი, სიმბოლოები
5. **Boundary Testing (ზღვრული მნიშვნელობების შემოწმება)** — min/max სიგრძე, დიაპაზონი
6. **დუბლირება** — ყველა სტატუსის მიუხედავად (active/inactive/cancelled)
7. **Read-only (მხოლოდ წასაკითხი)** — სადაც ჩანართი/გვერდი მხოლოდ დათვალიერებისთვისაა
8. **სერვისის შეცდომა** — ინტეგრაცია მიუწვდომელია / Loading State (ჩატვირთვის მდგომარეობა)
9. **ცარიელი მდგომარეობა** — ჩანაწერები არ არსებობს
10. **სტატუსის ცვლილების მატრიცა** — ყველა დაშვებული და დაუშვებელი გადასვლა
11. **უფლებების მართვა** — ყველა მოქმედება (დამატება, დათვალიერება, რედაქტირება, წაშლა, სტატუსი)
12. **ისტორიული მონაცემები** — სადაც სთორი ამას ითვალისწინებს

**ფილტრი, ძებნა, პაგინაცია** — ემატება მხოლოდ მაშინ, როცა სთორი ამას ცალსახად ითვალისწინებს და მომხმარებელი ადასტურებს scope-ში (გაშუქების არეალში) ჩართვას.

## სიის / რეესტრის გვერდის Edge Cases (სასაზღვრო შემთხვევები)

როცა სთორი მოიცავს სიის/რეესტრის გვერდს, **სავალდებულოდ** გადაიხედება:

### ძებნა
- ნაწილობრივი მნიშვნელობა (partial match / Boundary)
- რეგისტრის მიუხედავად (case-insensitive, ქართ./ლათ.)
- სპეციალური სიმბოლოები / whitespace-trim / არასწორი input
- შედეგის გარეშე ძებნა (negative — უარყოფითი სცენარი)

### ფილტრი
- ცალკეული ველის ფილტრი (representative, incl. ცნობარის მნიშვნელობები)
- ცარიელი/conditional ველის ქცევა ფილტრში
- თარიღის დიაპაზონი — არასწორი (from > to, negative — უარყოფითი სცენარი)
- ფილტრების კომბინაცია (AND ლოგიკა)
- ფილტრის გასუფთავება / reset (გასუფთავება)
- ფილტრი შედეგის გარეშე (negative — უარყოფითი სცენარი)

### სორტირება
- რიცხვითი და ტექსტური სვეტი ორივე მიმართულებით (representative)
- თარიღული სვეტი (ბოლოს დამატებული / განახლებული)
- role-restricted სვეტზე სორტირების მიუწვდომლობა

### სვეტების მართვა
- დამალული სვეტის გამოჩენა / გამოჩენილის დამალვა
- კონფიგურაციის შენარჩუნება refresh (გვერდის განახლება) **და** ხელახლა შესვლის შემდეგ

### ექსპორტი (Excel)
- დეფოლტ ხედით ექსპორტი (happy path — წარმატებული სცენარი)
- დადებული ფილტრის + ძებნის გათვალისწინება
- გამოჩენილი/დამალული სვეტების გათვალისწინება
- სორტირების მიმდევრობის შენარჩუნება ფაილში
- ცარიელი სიის ექსპორტი (negative — უარყოფითი სცენარი)
- ექსპორტის შეცდომა / სერვისის მიუწვდომლობა (negative — უარყოფითი სცენარი)
- ექსპორტის მოცულობის ლიმიტი (თუ სთორი განსაზღვრავს)

### ინტეგრირებული სცენარი (სავალდებულო)
- სორტირება + ფილტრი + ძებნა ერთდროულად

### უფლებები (role-restricted სია)
- თითო დონისთვის: ხილული ჩანაწერების scope (არეალი) + ხელმისაწვდომი სვეტები/ფილტრები (positive — დადებითი სცენარი)
- role-restricted მონაცემზე პირდაპირი წვდომა URL/ID-ით (negative — უარყოფითი სცენარი)
- ექსპორტი ხელმისაწვდომობის დონის შესაბამისად

> ⚠️ დაუზუსტებელი პუნქტები (დოკუმენტში „დასაზუსტებელია") — ქეისი მაინც იწერება default ქცევის დაშვებით, მაგრამ გეგმის წარდგენისას ცალკე ჩამოთვლი.

## Out of Scope — ავტომატური გამონაკლისები

- რედაქტირება, თუ ის ცალკე ტიკეტია
- ორგანიზაციული წვდომა, სანამ როლების ფუნქციონალი არ არის მზად
- ინტეგრაციის ტექნიკური დიზაინი
- სხვა მოდულის შიდა ლოგიკა (პროდუქტ-სპეციფიკური; იხ. მიმდინარე პროექტის CLAUDE.md)
- ნებისმიერი სხვა, სთორიში Out of Scope-ად მონიშნული

## Known Issue — ნიმუში

თუ დეველოპერის კომენტარი ადასტურებს ცნობილ ხარვეზს:
- `priority` = `low`, `severity` = `minor`
- `preconditions`-ში: `Known Issue: [აღწერა]`
- `behavior` = `positive` (ვაფიქსირებთ ამჟამინდელ ქცევას)
